# DESIGN

Как устроено приложение и почему именно так. Четыре раздела по README задания: отмена запросов, задержка debounce, сложность `mapCountryResponse` и принципы чистого кода.

Приложение разделено на два слоя:

- `src/core/` — логика без DOM: запрос, отмена, маппинг, классификация ошибок, контроллер. Тестируется в Node, сеть подменяется.
- `src/ui/` — отображение: строит DOM из состояния `ViewState` и передаёт действия пользователя контроллеру.

Цепочка данных: поле ввода → `controller.input()` → `debounce` → `searchCountries` → `mapCountryResponse` → `ViewState` → `renderState()`.

## 1. Отмена устаревших запросов: как и почему не флагом

### Как устроено

- Каждый запрос получает собственный `AbortController` (`startRequest` в [search-controller.ts](src/core/search-controller.ts)).
- `abortActiveRequest()` вызывается первой строкой `input()`, то есть на **каждое** изменение поля, до `debounce`. Старый запрос отменяется сразу, пока новый ещё ждёт своей очереди, и устаревший ответ не успевает прийти за время ожидания.
- Пустой ввод тоже проходит через `debouncedRun('')`. `debounce` оставляет аргументы последнего вызова, поэтому пустая строка вытесняет отложенный `'spain'`, а `run('')` ничего не делает. Отдельной переменной «актуальный запрос» для этого не нужно, один источник правды.
- Таймаут живёт внутри `searchCountries` ([search-countries.ts](src/core/search-countries.ts)): сигнал вызывающего кода склеивается с `AbortSignal.timeout()` через `AbortSignal.any([signal, AbortSignal.timeout(timeoutMs)])`. Каждый вызывающий получает таймаут автоматически, забыть его нельзя.
- [classify-error.ts](src/core/classify-error.ts) различает причины по `name`: `AbortError` (мы сами отменили) и `TimeoutError` (сервер не ответил за `DEFAULT_TIMEOUT_MS`). Это разные случаи: первый молчит, второй показывается с кнопкой «Retry».
- `aborted` не попадает в состояние экрана **на уровне типов**: в [view-state.ts](src/core/view-state.ts) у состояния `error` поле `kind` имеет тип `Exclude<ErrorKind, 'aborted'>`.

### Почему не флагом

Флаг вида «показывать только последний ответ» прячет устаревший ответ, но сам запрос продолжает лететь: он занимает сеть и сервер, а ответ приходит в любой момент и зависит от правильности каждой проверки в коде. `abort()` останавливает запрос по-настоящему: в Network он помечен `canceled`, а промис отклоняется с `AbortError`. В обработчиках ответа нет проверок «актуален ли ответ»: устаревшему ответу попросту некуда прийти.

### Граница ошибок держится на устройстве `.then`

`classifyError` считает любой `TypeError` сетевой ошибкой: `fetch` отклоняется именно им во всех браузерах, а текст сообщения у каждого свой («Failed to fetch», «NetworkError when attempting to fetch resource.», «Load failed»). Но `TypeError` бросает и обычная ошибка в коде, например `undefined.map`, и принимать её за потерю сети нельзя.

В контроллере нет `try`, запрос обрабатывается так: `search(query, signal).then(onSuccess, onError)` в `startRequest`. Второй аргумент `.then` ловит **только отклонение промиса `search`**. Ошибка, брошенная внутри `onSuccess` (например, в `mapCountryResponse`), до `onError` не доходит и в `classifyError` не попадает, поэтому свой `TypeError` не станет сообщением «No connection». Он останется необработанным отклонением, заметным в консоли. Границу держит сама форма `.then(onSuccess, onError)`, а не дисциплина «не расширять `try`». Если переписать на `async/await` с общим `try/catch`, граница пропадёт, и это нужно будет учесть.

### Как это проверено

[search-race.test.ts](src/core/search-race.test.ts) соединяет настоящие контроллер, `searchCountries` и `AbortController`, подменяя только `fetch`. Мок реагирует на `signal`: при `abort()` его промис отклоняется значением `signal.reason` (`AbortError`), как у настоящего `fetch`. Ответ на старый запрос в тесте приходит позже ответа на новый, и в итоге на экране результат только по последнему запросу. Так тест отличает настоящую отмену от игнорирования устаревшего ответа.

Проверка на пустоту: если убрать вызов `abortActiveRequest()` из `input()`, красными становятся 9 из 11 тестов гонки.

## 2. Задержка debounce = 300 мс

Значение лежит в константе `DEFAULT_DEBOUNCE_MS` ([search-controller.ts](src/core/search-controller.ts)) и меняется параметром `debounceMs`.

**Что `debounce` делает и чего не делает.** Правильность не зависит от него: даже без `debounce` устаревший ответ не покажется, потому что каждый ввод отменяет предыдущий запрос (раздел 1). `debounce` нужен, чтобы не создавать лишнюю нагрузку и не мигать экраном.

**Почему 300 мс.** Это компромисс между двумя границами. При непрерывном наборе паузы между буквами обычно короче 300 мс, и пока человек печатает, запросы не уходят. Когда он остановился, 300 мс ощущаются как мгновенная реакция. Значение выбрано по общепринятой практике, замеров на пользователях я не делал.

**Что будет без `debounce`.** Каждая буква отправляет запрос: на `spain` их пять. Короткие запросы дают самые тяжёлые ответы: поиск идёт по подстроке, поэтому на запрос `s` API отвечает 107 странами, а на `spain` одной (проверено запросами к `https://countries.dev/name/…`). Каждый такой ответ нужно отрисовать, и экран мигает: загрузка, список, загрузка, новый список. Остальные запросы отменяются, но уже успевают стоить серверу работы, а публичный API без ключа может начать ограничивать частоту запросов (ответ 429). Лимитов этого API я не проверял, это предположение.

**Что будет при 2000 мс.** Нагрузка минимальна, но приложение выглядит зависшим. Индикатор «Loading…» появляется сразу на ввод, а запрос не уходит ещё две секунды: человек видит крутящийся индикатор, за которым ничего не происходит. Живой поиск превращается в поиск «по кнопке».

## 3. Big O для `mapCountryResponse`

Пусть у одной страны `l` языков, `c` валют и `b` границ.

[map-country-response.ts](src/core/map-country-response.ts) проходит по каждому списку ровно один раз:

- `languages`: один проход `flatMap`, O(l);
- `currencies`: один проход `flatMap`, `formatCurrency` на элемент выполняется за O(1), O(c);
- `borders`: одна копия через spread, O(b);
- остальные поля (`name`, `region`, `population`, `area`, флаг) и `buildDescription` сводятся к фиксированному числу операций, O(1).

**Одна страна:** время O(l + b + c), память O(l + b + c): новые массивы того же размера, исходный объект не меняется.

**Ответ из n стран:** контроллер вызывает `countries.map(mapCountryResponse)`, то есть функция выполняется n раз независимо. Итого O(Σ(lᵢ + bᵢ + cᵢ)) = O(n · (l + b + c)) по максимальным длинам списков. Вложенных проходов по n стран нет (нет сортировки или поиска внутри), поэтому квадратичной зависимости от n не возникает. У реальной страны каждый из списков ограничен небольшой константой (границ у одной страны не больше нескольких десятков), поэтому на практике это **O(n)**.

Отрисовка списка тоже линейна: по одному набору DOM-узлов на карточку.

## 4. Принципы чистого кода

### Единая ответственность (SRP)

- [map-country-response.ts](src/core/map-country-response.ts): `formatCurrency` форматирует одну валюту, `getKind` выбирает «a territory / an independent country / a country», `buildDescription` собирает фразу. Сама `mapCountryResponse` только собирает карточку из этих частей.
- UI разделён на четыре файла, у каждого своя задача:
  - [dom.ts](src/ui/dom.ts) — общий помощник `element`: как построить элемент.
  - [components.ts](src/ui/components.ts) — из чего состоят карточка страны и страница деталей.
  - [render.ts](src/ui/render.ts) — что показать в каком состоянии.
  - [app.ts](src/ui/app.ts) — создание поля и области один раз, подписка на контроллер.
- Один модуль — одна причина измениться: [debounce.ts](src/core/debounce.ts), [http-error.ts](src/core/http-error.ts), [classify-error.ts](src/core/classify-error.ts), [error-messages.ts](src/ui/error-messages.ts).

### Никаких магических чисел и строк

Именованные константы вместо голых значений: `DEFAULT_TIMEOUT_MS` и `NOT_FOUND_STATUS` в [search-countries.ts](src/core/search-countries.ts), `COUNTRIES_API_URL` там же, `DEFAULT_DEBOUNCE_MS` в [search-controller.ts](src/core/search-controller.ts), `NO_DATA` в [format.ts](src/ui/format.ts). Комментарий к `DEFAULT_TIMEOUT_MS` объясняет выбор 10 секунд.

### Логика отдельно от отображения

В данных пустое значение — это `null` или `[]` ([country-card.ts](src/core/country-card.ts)): логика не знает, как оно выглядит на экране. Символ «-» (`NO_DATA`), `Intl.NumberFormat('en-US')` и «km²» добавляет только UI в [format.ts](src/ui/format.ts), поэтому `0` остаётся настоящим значением, а `null` отличается от него. Папка `src/core/` не обращается к DOM, поэтому её тесты работают в Node без браузера.

### Никакого `innerHTML`

Весь динамический текст попадает на страницу через `element()` в [dom.ts](src/ui/dom.ts): текст — через `textContent`, атрибуты — через `setAttribute`. Во всём `src` нет `innerHTML`, `outerHTML` и `insertAdjacentHTML`, поэтому строка из API или из поля ввода не может стать разметкой.

### Исчерпывающий `switch`

`renderState` в [render.ts](src/ui/render.ts) закрыт веткой `default` с переменной типа `never`. Новое состояние в `ViewState` без отрисовки не пройдёт `tsc` на коммите. Так же устроена `ERROR_MESSAGES: Record<kind, string>` в [error-messages.ts](src/ui/error-messages.ts): новый вид ошибки без текста не соберётся.

### Зависимости передаются снаружи

`createSearchController({ search })` принимает функцию поиска параметром, а не импортирует её. В приложении туда передаётся `searchCountries`, в тестах фейк, поэтому гонка проверяется без сети. [classify-error.ts](src/core/classify-error.ts) и [map-country-response.ts](src/core/map-country-response.ts) — чистые функции без побочных эффектов.

### Состояние несёт свои данные

Каждое состояние `ViewState` хранит всё нужное для экрана. В `error` лежит `query`, поэтому «Retry» повторяет именно последний запрос и не зависит от текущего текста в поле. В `details` лежат `cards`, и «Back» возвращает тот же список без нового запроса.

## Известные ограничения

- Ответ API проверяется только на то, что это массив (`Array.isArray`). Форма каждой страны не валидируется, а `as CountryResponse[]` — это утверждение типа, а не проверка.
- После «Back» фокус не возвращается на карточку, с которой открывали детали. При открытии деталей фокус переходит на кнопку «Back».
- `role="status"` на вставляемых элементах (подсказка, загрузка, «ничего не найдено») не все экранные дикторы объявляют надёжно. Ошибка использует `role="alert"`.
